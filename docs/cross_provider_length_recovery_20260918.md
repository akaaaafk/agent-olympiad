# 跨比赛、跨接口的长度恢复修复（2026-09-18）

## 结论与范围

本次修复针对生成、工具传输和保存之间的长度契约不一致，不修改评分、不提高比赛资源上限，也不把 OTC 策略加入普通 baseline。先用离线测试复现，再修改实际传输路径并补回归。

原有 ARML `work` 上限调整到 8000 字符，不等于所有比赛、所有工具都应该使用 8000。本次沿用已有配置：普通草稿通常为 8000；论文、长证明等交付使用自己的配置（当前矩阵为 60000）；源代码任务不套普通草稿上限，但仍受模型输出、比赛预算和原有工具约束。

## 已确认的缺口与修复

1. **原生工具调用绕过长度恢复。** 完整 JSON 不代表参数符合保存限制。现在在交给执行器之前按字段和整体 payload 校验；超限后最多进行一次专门编辑。只开放原工具，固定题目和其他参数，重新校验 schema，仍不合格就不执行。
2. **混合源代码/普通任务丢失草稿限制。** 保留源代码豁免，同时传递按 task 定义的限制；普通任务的超限草稿不能借源代码任务的豁免通过。
3. **Tinker 与原生路径使用不同的长度逻辑。** 新增 `argument_limits.py` 作为公共契约，复用字段/整体长度计算、错误说明与编辑提示。Tinker 已有的分阶段动作、完整 token 续写和预算机制保留，外层不再额外启动一轮恢复。
4. **结构化参数超限导致 Tinker 游标越界。** 最后一个 metadata 字段先校验，成功后再推进游标，避免 `IndexError`；失败时只重写该字段，并保存恢复状态。数组长度、对象键、标识符和数值变化不能冒充结构保持的编辑。
5. **PDF 页证据超限后的反馈不足。** 重试给出实际字符数、硬上限、较低目标及完整被拒文本。3200 字符/批、24000 字符总证据上限、每批两页和最多两次尝试保持不变；实际每批限额可能因总页数更低。不可读或不完整响应不能变成有效评分。

长度编辑要求保留原答案、证据与不确定性，不重新解题；完整原文作为数据输入，不能静默裁切为可执行动作。结构检查不能证明自由文本的语义完全不变，因此不宣称编辑绝不会引入语义误差。无法在约束内完成时仍明确失败。

## 预算、权限与历史结果

- 首次输出、失败重试及恢复输出都计入 API/token 用量；剩余额度不够就不再调用。供应商超报预算也记录实际消耗，但不接受动作。
- 总剩余 token 预算不再被误当成单次输出上限。原接口配置的单次上限保留；不靠无限扩容解决截断。
- PDF 分页收到请求级预算时，所有证据批次、重试和最终判断共享该预算。
- 原有动作权限、角色、阶段、状态门禁、多工具调用原子拒绝和熔断机制保留。
- 未修改比赛规则/数据上限，未覆盖历史付费结果，未启动新付费比赛，也未重启旧 checkpoint。
- 协议标记更新为 `argument_limits=1`、`action_transport=2`、`work_content=2`、`staged_raw_arguments_v6_shared_limits`、`pdf_page_evidence_v2_length_recovery`。运行时身份和 PDF 缓存绑定使用更新后的版本，不将新旧协议视作同一次实验。

## 仍然存在的真实边界

模型可能继续输出过长、错误 JSON 或无工具调用；上下文窗口、模型采样上限和比赛预算也不可消除。本次目标是消除框架的长度契约缺口，允许有界、可审计的恢复，同时保证失败时不执行半截动作、不偷改答案长度、不伪造成功或分数。
